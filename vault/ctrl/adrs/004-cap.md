## §1 Mcp execution — MCP outward / Actor inward

**Outward protocol = MCP** (Anthropic Model Context Protocol). **Inward runtime = Actor** (one of ADR-001 §2's 5 primitives).

- **MCPServerActor** = well-known `Actor` subclass wrapping an MCP server. Not a 6th primitive.
- **4 mcp sources** (ADR-001 §3 v9) — MCP / OAuth / Local agent / Builtin — all express uniformly as MCP servers. ST-SS is retired as a source; implementation differences are absorbed in MCPServerActor subclasses (SubprocessActor for Pattern B/C/D, OAuthCapability for Pattern E).
- **v1 sandbox** = OS-level (macOS sandbox-exec / Linux landlock+seccomp / Win AppContainer) with capability gates declared in manifest. Missing capability → syscall block.
- **WASM** demoted from default to optional high-security actor impl. v1.x re-evaluation = WasmEdge if needed.

Day-1 compatibility with Anthropic MCP ecosystem (10K+ servers). Irisy / Claude Code / Cursor / any MCP host invokes mcps with no integration code. Creators write MCP once, runs everywhere.

## §2 Tauri 2 updater + three-mirror channel

Self-update = **Tauri 2 authenticated metadata/download + CTRL-owned macOS in-place transaction** + **three-mirror endpoint array (ordered fallback)** + **three channels (stable / beta / dev)** + **per-user update (no installer UI/UAC)** + **signing key in macOS keychain**.

**Mirror priority order**:
1. Tokyo Caddy (`updates.ctrlapplab.com`)
2. CF Worker + R2 (`ctrl-updates.workers.dev`)
3. GitHub Releases

**Channel switching**: `~/.ctrl/state/update-channel` file (PWA Settings toggle). URL embeds channel segment.

**Signing and trust epoch**: the updater's active private key is in macOS Keychain `tauri-sign / ctrl-updater`; the public key is pinned in `src-tauri/tauri.conf.json` `plugins.updater.pubkey`; and `scripts/updater-trust.json` tracks only the non-secret epoch and active minisign key id. Release preflight must prove that the active private key signs for the pinned public key, that both identify the tracked epoch, and that an encrypted recovery copy exists, matches its hash receipt, decrypts, and byte-matches the active key. The recovery payload uses AES-256-CBC with PBKDF2 (200,000 iterations); its independent random passphrase and receipt are separate Keychain items, and the encrypted payload is stored outside the source tree for external backup. No secret or recovery credential enters Git, logs, release metadata, or LLM context.

**macOS release identity epoch**: code signing has an independent continuity boundary. `scripts/macos-signing-trust.json` tracks the non-secret epoch, certificate fingerprint, label, and predecessor; `bundle.macOS.signingIdentity` pins the same fingerprint. Release preflight must find that exact identity in the canonical login Keychain, prove its encrypted PKCS#12 backup hash and certificate/private-key pair, and complete a bounded real `codesign` probe. The backup passphrase and receipt are separate Keychain items; the encrypted payload has one fixed durable location outside source/temp trees. The active private key is imported only into the canonical login Keychain with `/usr/bin/codesign` authorization, avoiding an unrecoverable custom-Keychain password. If the private key is permanently inaccessible, `scripts/reset-macos-signing-identity.sh` is the only reset path: it requires explicit acknowledgement that macOS privacy permissions may need reauthorization, preserves `app.ctrl.spike`, establishes and verifies backup evidence before activation, ratchets the identity epoch, and uses a phased fsync-backed journal to durably complete or roll back an interrupted reset. The certificate-bound Designated Requirement changes once at reset and is stable again within the new epoch. `scripts/restore-macos-signing-identity.sh` restores a missing recoverable identity without rotation. The inaccessible predecessor keychain remains untouched as historical evidence. This self-signed identity governs the local development release channel and canonical install on the operator account; it does not claim Gatekeeper acceptance on a clean recipient. Production distribution still requires the separately tracked Developer ID/notarization acceptance item. (ADR-004 cap § updater v9)

**Ordinary macOS in-place transaction**: Tauri owns endpoint selection, version comparison, archive download, and minisign authentication; CTRL owns the post-download filesystem transaction and does not call `Update::install` on macOS. The signed archive is extracted into a mode-0700 sibling of `/Applications/CTRL.app`; entry count and expanded bytes are bounded, every member remains under the single `CTRL.app` root, duplicate/special entries are rejected, and relative symlink/hard-link targets must normalize inside that bundle. Before live mutation, CTRL verifies the staged identifier, strict deep code signature, active certificate-root requirement, non-ad-hoc Authority, non-`cdhash` Designated Requirement, and the exact release version accepted by the user; concurrent native apply attempts are rejected. A mode-0600, fsync-backed sibling journal records prepared/swapped/launching/rolling-back/healthy/rolled-back/rollback-failed phases. Every rollback persists `rolling_back` before process or bundle mutation; startup compares canonical and staged versions to resume an unperformed rollback or finalize an already restored previous bundle, so a crash cannot invert the swap from stale journal state. `renamex_np(RENAME_SWAP)` atomically exchanges the staged and canonical bundles on one volume, so the canonical path never disappears. The old signed executable runs a pre-Tauri helper from the retained rollback bundle; after single-instance arbitration admits the replacement, an exact transaction-token argv authorizes it to record its PID before shell boot and acknowledge health only after shell boot plus version/identity re-verification. Helper, candidate, and old-app lifecycle decisions persist and revalidate PID plus kernel process-start timestamp and executable path, together with the expected arguments, immediately before signalling; a numeric PID or matching command text alone is never process identity. The helper cleans the old bundle only after that acknowledgement. Failed verification, launch, timeout, or boot terminates only the matching candidate and atomically restores/reopens the prior bundle; a failed termination or rollback preserves both bundles and the journal. A replacement startup reattaches a missing helper through a token-bound relaunch, while an un-tokened duplicate cannot claim candidate ownership; a recovered healthy transaction completes cleanup. This is the normal updater path—no DMG, installer wizard, privileged service, manual copy, or migration script. (ADR-004 cap § updater v10)

Ordinary macOS in-place transaction remains the sole production path. True-machine debugging uses a separately compiled, signed A/B channel behind the non-default `updater-debug-channel` Cargo feature. Only that feature may replace the metadata endpoint with an embedded `http://127.0.0.1:<port>/latest.json` value or consume one-shot fault markers from `~/.ctrl/state/updater-debug-fault`; supported markers cover pre-candidate launch rejection, suppressed health acknowledgement, and interruption after durable `rolling_back` intent. The local builder must reuse both active signing epochs, verify app/archive trust, keep all artifacts under `src-tauri/target`, and perform no Git tag/push, GitHub release, or tracked production endpoint mutation. Production release rejects debug-channel environment and never enables the feature. (ADR-004 cap § updater v11)

**Release-operator canonical acceptance**: after the signed public archive and `latest.json` have been downloaded and re-verified as one provenance-bound pair, the operator release flow performs the existing verified canonical-path install, opens `/Applications/CTRL.app`, and proves the target version, strict signature/identity, and launched canonical executable path. Failure leaves the release incomplete; it must not be described as installed or ready for experiential testing. This is local release-operator acceptance only, not a second ordinary-user updater path. (ADR-004 cap §2 v12)

**Irrecoverable-key reset**: updater signing verification cannot be disabled and a replacement private key cannot authenticate to a client that pins the lost key. `scripts/reset-updater-trust.sh` is therefore the only updater-key reset path: it requires explicit acknowledgement that old clients need reinstall, starts from a clean source, generates a fresh key, establishes and verifies the encrypted recovery copy before updating the pin, and ratchets the tracked updater epoch/key id. The bundle identifier does not change. The macOS release identity follows its independent identity epoch above: it stays fixed unless its own private key is inaccessible and the explicit v9 reset protocol is executed. Every installation from an earlier updater epoch receives one provenance-, SHA-256-, updater-signature-, and active-macOS-identity-verified atomic replacement at the canonical path with rollback backup; it must not be described as a Tauri updater operation. Once that replacement runs, ordinary signed in-place updates resume inside both active epochs. Unsigned fallback, silent key replacement, and reconstructing a private key from public artifacts are forbidden. (ADR-004 cap § updater v9)

**v1 ship reality**: single-mirror `soodooi/CTRL-releases` only. 3-mirror failover deferred to v1.1 (gated on CN P95 SLO + bao budget for Win OV signing ~$200-400/yr).

### Release governance baselines

A release carries three independent trust boundaries; one commit must not be overloaded to mean all three:

1. **Provenance base** — the exact source commit proven by the previous public release body, immutable `vX.Y.Z-release` tag, `latest.json`, and optional `source-provenance.json`. It establishes ancestry and artifact lineage.
2. **Secret base** — the provenance base. Added-secret scanning covers the complete previous-public-source → target-source delta and is never grandfathered.
3. **Citation base** — normally the previous proven public source. During the one-time migration from a public source predating executable citation governance, it is the immutable activation commit `0beef42d92672be342b9a92b56132737e7e8a050` (`scripts/check-governance.mjs` introduction). After the first successful governed release, the previous public source is newer than the epoch and the normal per-release ratchet resumes automatically.

The citation epoch is a forward-enforcement boundary, not release provenance: its single executable source of truth is `scripts/governance-policy.json`; it must resolve to an ancestor of the target and cannot be supplied or moved by an operator environment override. First-migration discovery is read-only until Release Acceptance, full-delta secret scanning, epoch-delta citation scanning, worktree governance, compiler checks, and tests all pass. Only then may the script publish a missing historical source tag or provenance sidecar. `ADR_AUDIT_SOFT=1` changes only Acceptance reporting and never bypasses provenance, secret, citation, compiler/test, signing, or public read-back gates. (ADR-004 cap § Release governance baselines v7)

Rust citation analysis uses Rustfmt-normalized before/after source only to distinguish layout churn from semantic Rust hunks. It never changes raw added-line secret coverage: the full provenance delta is scanned and reported first, including when Rustfmt cannot normalize a changed file. Every remaining normalized substantive Rust hunk still requires a nearby resolvable ADR citation; formatter failure then blocks the check fail-closed. (ADR-004 cap §2 v12)

## §6 Signature + integrity (Layers 2-3)

- Layer 2 (external agents): pinned upstream package/artifact + ACP contract probe + L3 approval (ADR-002 §1.8.4)
- ~~Layer 3 (mcp): per-mcp signing key (creator-supplied), public key in `manifest.signing.pubkey`; kernel rejects update if signature fails~~ **SUPERSEDED v3 — this was the key-swap anti-pattern.** A verification key carried *inside the bundle it verifies* lets an attacker re-sign with their own key + replace the embedded pubkey, so verification always passes (NIST CSWP code-signing; US Pat. 7,552,342). The key must live OUTSIDE the bundle.

### §6.1 Pack supply-chain trust model (v3, 2026-06-26 — red-team C1 supply chain)

Research (`vault/ctrl/research/pack-supply-chain-trust.md`, 2026-06-26): mature mechanisms were scored against CTRL's hard constraints (no account, local-first, multi-source, `.mcpb` zip, plain-text). **Sigstore keyless** needs an OIDC *account* (Google/GitHub) → rejected. **Full TUF** needs a live online metadata/timestamp pipeline per source → too heavy for v1 + third-party authors. **npm provenance** needs central registry + cloud CI → rejected. **Registry signing root** = a central trust locus CTRL avoids. The `.mcpb` spec itself carries **no** signature/hash field, and the MCP Registry signs *nothing* (verifies namespace identity only). Closest live analog = **Obsidian community plugins** (local-first, third-party-dominant, no enforceable sandbox, default-off Restricted Mode + author-hosted releases).

**Decision: minisign/signify-style detached Ed25519 + TOFU key-pinning + mandatory sha256 hash-pin + default-deny install gate.** Account-free, offline, multi-source-uniform, `vim`/`git diff`-inspectable, uses the unsigned `.mcpb` as-is (signature is a sidecar, no format fork). Borrows TUF *ideas* (per-source root, forward-chained key rotation, threshold for high-value packs) without running TUF's servers.

**v1 (no registry) — install-time verification:**
1. **[SHIPPED v3] sha256 hash-pin** — `install_mcpb_blocking` hashes the bundle before trusting it + writes `~/.ctrl/mcps/<id>/installed.json {bundle_sha256}` (git-diffable). Closes the "unzip with zero verification" gap. Integrity, not authorship.
2. **Detached Ed25519 signature** over the bundle hash (minisign/signify-compatible, sidecar file; trusted-comment = pack+version+author fingerprint). **Verification key NEVER inside the `.mcpb`** — author publishes pubkey out-of-band (repo root `minisign.pub`, ≥2 channels).
3. **TOFU key-pin** — pin author fingerprint on first install (`~/Documents/CTRL/.trust/packs.toml`, signed by the user's Keychain identity so a malicious pack can't edit it); same key (or forward-chained successor) required on every update; different unsigned key → block + plain-text old-vs-new fingerprint warning.
4. **Default-deny gate** before any pack code runs (Obsidian Restricted Mode): a fresh pack is inert until the user approves; approval screen shows fingerprint + hash + (for MCP packs) the *full* tool descriptions the model will see — defeats MCP tool-poisoning / rug-pull (Invariant Labs / Trail of Bits: re-hash tool descriptions each server start, diff vs the approved pin).

**Revocation (v1, no server):** forward-chained key rotation (`next_pubkey`, signify model) → rotate with no revocation server; local kill via TOFU pin mismatch; opportunistic **CTRL-signed** `revoked-hashes` denylist (the one justified CTRL-held key — for CTRL's own release artifacts, not user identity).

**v1.1 (with MCP Registry / `.well-known`):** adopt registry namespace identity (`.well-known/mcp-registry-auth`, GitHub OIDC trusted-publishing) as a *second* trust signal that shrinks the first-contact window — NOT a replacement for CTRL's own sig+hash (registry signs/scans nothing). Graduate first-party `ctrl-<name>` packs to TUF-style threshold + offline root.

**Residual (state plainly):** first-install/first-contact trust is irreducible without a central PKI (TOFU + wide out-of-band key dispersion mitigates, doesn't cure); TOFU does not stop a *legitimately-signed* malicious update (→ default-deny gate + no-sandbox honesty); signing is integrity+continuity, not content-safety (pair with the `:17873` gate + OS sandbox for runtime containment).

## Release Acceptance (§2)

- [x] The isolated local A/B harness builds strictly signed baseline/candidate apps and a pinned-key-verifiable candidate archive from the current tree, emits loopback-only metadata under `src-tauri/target`, exposes compile-time-gated one-shot launch/health/rollback-interruption faults, and proves the tracked production endpoint and public release state are untouched.
