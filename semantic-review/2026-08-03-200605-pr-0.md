# Isolated Irisy/OpenCode dialog and private LibreOffice source

This slice puts Irisy and OpenCode in one persistent dialog with separate transcripts, ACP clients, cancellation registries, and workspace ownership. It also makes Coding projection opt-in, retires stale projection artifacts, materializes release-owned skills, and adds a read-only LibreOffice selection source behind a private loopback bridge. First-run bridge bootstrap, retirement ownership, and reset ordering still violate accepted behavior. **Result: NEEDS_CHANGES.**

**Watch for:** **confirmed** LibreOffice cannot bootstrap its first keychain credential; **confirmed** projection retirement can delete a user-owned replacement named `ctrl-kernel`; **likely** fire-and-forget Irisy and Coding resets can race a new turn across session/workspace boundaries; **confirmed, non-blocking** `AGENTS.md` retirement is not crash-atomic.

## High-level view

The modes keep separate durable stores and backend singleton slots, and Coding cancellation is request-owned. The remaining boundary risk is transition ordering: the UI exposes the newly selected owner before its old engine reset completes, while Irisy reset has no epoch/cancellation guard.

LibreOffice selected content stays in the extension-to-private-adapter path, and the adapter is hidden from public MCP discovery. Its clean-install token lifecycle is circular: the extension requires the token before publishing rendezvous metadata, while the kernel creates the token only after validating that metadata.

Projection eligibility correctly requires `projection.coding_workspace == true`, but retirement identifies JSON ownership only by the public key `ctrl-kernel`. A user replacement under that key is indistinguishable from CTRL's generated entry and is removed.

Release-owned skills use one bundled authority with atomic materialization and user precedence. Unit, type, compile, syntax, and ADR soft checks pass, but none covers the transition and bootstrap failures.

## Engine reset ordering leaves UI ownership ahead of ACP ownership

Irisy session switching aborts the frontend controller and calls `resetEngine()` without awaiting it (`packages/ctrl-web/src/components/ambient/AmbientHome.tsx:395-396`); new chat, resume, and fork repeat this at lines 484, 501, and 514. The backend reset only waits for the singleton lock and sets the client to `None` (`src-tauri/src/commands/irisy_chat.rs:125-126`), with no ownership epoch or cancel/drain. **Likely:** a new-transcript turn can queue against the old client or be followed by the delayed reset. Await completion or make the backend transition epoch-owned before accepting the new owner.

Coding has stronger backend epoch/cancellation handling, but `confirmWorkspaceChange()` starts reset and immediately exposes the new workspace (`packages/ctrl-web/src/components/coding/CodingAgentPanel.tsx:411-414`); the composer remains enabled. **Likely:** a prompt can dispatch for the new path before reset obtains the singleton lock, using the stale process or being cancelled by the following reset. Await reset, disable submission, and surface failure.

**Confirmed:** no component/integration test covers these transitions. Frontend tests cover stores/launchers, while Rust Coding tests cover the capability brief rather than concurrent ownership.

## LibreOffice credential creation has a clean-install deadlock

Companion raises “Start CTRL once” when the `app.ctrl` / `libreoffice-bridge` item is absent, then reads that item before binding the server or publishing rendezvous metadata (`packages/ctrl-mcps/optional/ctrl-libreoffice/extension/ctrl_companion.py:171,353`). The only creation path found is `ensure_bridge_credential()`, but kernel resolution first requires `read_validated_rendezvous(&path)` and creates the credential afterward (`src-tauri/src/kernel/libreoffice_bridge.rs:99,105,120-134`). **Confirmed:** on a clean profile neither side can satisfy the other's prerequisite. Provision the item during trusted CTRL startup/installation before Companion enablement, and add a clean-profile test.

## Retirement treats a key name as proof of ownership

`remove_managed_json_entry()` removes `ctrl-kernel` unconditionally (`src-tauri/src/kernel/projector.rs:581-600`). **Confirmed:** if a user replaces CTRL's generated value under that key, making the pack ineligible deletes the user's value. The test preserves only a differently named sibling. Persist or recognize a CTRL-owned signature; otherwise preserve the entry and warn.

`remove_managed_agents_block()` rewrites surviving prose with `fs::write` (`src-tauri/src/kernel/projector.rs:614-631`) instead of atomic sibling-write/rename. **Confirmed, non-blocking:** a crash or write failure can truncate `AGENTS.md`. Reuse an atomic writer.

## Validation passes but does not prove these transitions

Web typecheck passed; 249 web tests in 31 files passed. Cargo check passed with one pre-existing dead-code warning; 549 Rust tests passed with 3 ignored. Adapter `node --check`, extension Python AST parsing, and `git diff --check` passed. The ADR soft audit reported only accepted ADRs' open acceptance items.

Not tested: clean-profile credential creation and real extension enablement; replaced `ctrl-kernel` retirement; crash-atomic `AGENTS.md` retirement; rapid submit during either reset; Playwright/visual persistent-dialog mode switching.
