# Single-truth capability-domain and user-intent registries (ADR-002 §17 v85, ADR-005 §12 v42, ADR-003 §8.5 v42)

The change makes two previously implicit vocabularies into accepted authority: ADR-002 §17 enumerates `system` plus 19 grantable capability domains and declares `src-tauri/src/kernel/visibility.rs` its implementation, and ADR-005 §12 enumerates 25 user intents (U1–U25) mapped onto those domains with `v1`/`later` scope. ADR-003 §8.5 v42 becomes a consumer: it decides which surface serves an intent, cites intent IDs, and explicitly loses the power to define product scope. The retired predecessor (ADR-005 §1's 8-stage "User intent" column) is banner-marked retired-v42 in the body and annotated in `sections` in the same change, and INDEX is synced for all three ADRs.

Watch for: `project` is granted in the first-party default but no classifier prefix maps to it (confirmed in code; declared honestly in §17.4), and ADR-005 U9 nonetheless names `project` as a `v1` primary domain (confirmed, tolerable only because `vault`/always-on verbs cover it). Separately, §17 does not state that the three always-on canonical verbs make domain grants non-load-bearing for Resource-level reach (confirmed from `visibility.rs`: `describe|query|produce` return `ALWAYS_ON`, and `BRAIN_TOOLSET` is exactly those three).

**Verdict**: APPROVED

## High-level view

Authority is single-sourced. §17.3 says domains authorize but do not enumerate product capability and defers enforcement placement to ADR-010 § trust-domains v14 and intent ownership to ADR-005; §12.3 says ADR-002 §17 owns the authorization vocabulary and ADR-003 §8.5 owns surface mapping; ADR-003 v42 states it cannot introduce a job absent from the registry. No competing live enumeration remains: the only other intent list (68 entries) sits in retired ADR-008, and ADR-010's trust-domains section carries domain names only in changelog provenance and an implementation-anchor table, not as a rival registry.

The §17.1 table matches the implementation exactly. `ALWAYS_ON = "system"` plus `FIRST_PARTY_DOMAINS` plus the prefix table plus `net`/`websearch`/`mcp` yields precisely the 20 rows (system + 19). Row semantics match code behavior: `notes` covers `note_`/`notes_`/`doc_`; `websearch` is exact-match `web_search` so a future `web_fetch` cannot inherit it; downstream `<server>_<tool>` and unclassifiable names resolve to `mcp` via `tool_domain_with_downstream`/fallback; `net` appears in no default grant (`FIRST_PARTY_DOMAINS`, `BYO_CLI_DEFAULT_INTENT`, `OPENCODE_CODING_INTENT` all exclude it); absent scope resolves through `default_for_caller` to first-party set or `minimal`, never full surface. The `source` row's "per-source authorization is not yet expressed" mirrors the code comment rather than papering over it.

The declared `project` gap is real and correctly characterized: `project` is in `FIRST_PARTY_DOMAINS`, but no `project_` prefix exists in the classifier table, and Project refs are reached through the always-on verbs (`mcp_server.rs` registers a `project` Resource kind, not `project_*` tools).

Intent→domain references all resolve: every domain named across U1–U25 (`system`, `vault`, `notes`, `smart_table`, `tasks`, `calendar`, `source`, `project`, `providers`, `registry`, `llm`, `memory`, `mcp`, `market`, `websearch`, `discover`, `skill`, `diagnostics`) exists in §17.1. `kv` and `net` are intentionally unreferenced, consistent with `kv` being internal state and `net` never granted.

PROCESS compliance holds: in-place section amendments, integer bumps (002 79→85, 003 39→42, 005 38→42), newest-first prepended changelog entries, `last_updated: 2026-08-05` matching the top entry, `sections` additions (`capability-registry`, `user-intents`, `intent-conformance`) plus retired-vN provenance entries, INDEX version/date/summary/module-map sync, and new backlog placed under `Design Acceptance (non-release, ...)` scopes rather than `Release Acceptance`. `bash scripts/check-adr-acceptance.sh --soft` parses the new scopes and reports them as open (soft WARN, expected). Lock points are untouched: §17.3 reaffirms the three verbs as the agent surface, §12.2 keeps U6/U19/U22 writes on ReviewGate, and no primitive, `:17873`, or plain-text invariant is amended.

Over-claiming: none found. §12.1 marks U22 write and U23–U25 as `later`, §12.2 forbids presenting `later` as available, ADR-003 v42's citation requirement is stated as a forward obligation rather than an achieved state, and both new Design Acceptance blocks are unchecked with an explicit "not release-completion claims" note.

### Domain table vs. `visibility.rs`

Implementation sources of domain strings, all covered by §17.1:

```text
ALWAYS_ON                = "system"
exact-match              describe|query|produce|kernel_status|vault_root_path -> system
                         web_search -> websearch
prefix table             smart_table_|task_|source_|irisy_soul_|vault_|notes_|note_|doc_|
                         calendar_|providers_|registry_|kv_|llm_|market_|discover_|skill_|
                         diagnostics_|http_|mcp_
fallback                 -> mcp
FIRST_PARTY_DOMAINS      vault smart_table tasks calendar source project notes providers
                         registry kv llm memory mcp market websearch discover skill diagnostics
```

Union = 20 tokens = `system` + 19 grants, exactly §17.1's row count. `task_ -> tasks` and `irisy_soul_ -> memory` are the only name/domain mismatches, and both are represented correctly in the table's domain column.

### Default grants and the `net` rule

§17.2's "`net` must never enter a default grant" is satisfied at all three grant sites. `BYO_CLI_DEFAULT_INTENT` = `vault,smart_table,tasks,notes,providers,registry,kv,llm,memory`; `OPENCODE_CODING_INTENT` adds `source,discover,skill,mcp,calendar`; `FIRST_PARTY_DOMAINS` adds `market,websearch,diagnostics,project`. The `CTRL_BYO_INTENT=unscoped` escape hatch omits the header rather than granting everything, and an omitted header for caller `byo-cli` resolves through `default_for_caller` to `minimal`, so it does not contradict "absent caller scope resolves to a declared default, never the full surface".

### Retired predecessor

ADR-005 §1 keeps its table but gains a heading rename (`retired-v42 intent provenance`) plus a blockquote forbidding citation for product scope, UI conformance, or capability mapping, and the `lifecycle` `sections` entry records `intent column retired-v42`. §12.3 additionally names the retired ADR-008 inventory, `irisy-architecture.md`, and §1's table as provenance that cannot reintroduce scope. That is archive-in-the-same-change, and no second live list survives.

### Code citation follow-up (not blocking)

`visibility.rs` cites `ADR-010 communication § trust-domains` and `ADR-002 substrate §15.4 v84`, but nothing yet cites `(ADR-002 substrate § capability-registry v85)` even though §17 declares that file its implementation. PROCESS §8 step 5 expects affected code citations to follow the amendment; the code is outside this review's file scope, so it is recorded here as the next slice's obligation rather than a defect in these ADR edits.
