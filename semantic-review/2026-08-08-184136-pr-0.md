# Decision surface registry for the Ambient shell

A new frontend-owned registry (`lib/decision-registry.ts`) closes a six-kind set — approval, unavailable, conflict, progress, choice, capture — and maps each kind to a presentation record (modal vs inline, tone, whether staged change and preconditions are shown). `DecisionSurface.tsx` is the single renderer for that contract; three adapters (`approvalFact`, `unavailableFact`, `conflictFact`) turn kernel-typed facts into the envelope without adding cross-boundary schema. `ReviewGateHost` swaps its hand-built `ConfirmDialog` for the registry, and `AmbientHome` replaces two fabricated assistant messages on FCT selection failure with an `unavailable` fact carrying a "Manage in Library" recovery action. ADR-003 is amended to v43 with a matching § decision-registry body, and INDEX is in sync.

Watch for: the approval path cannot satisfy the U10 requirement it claims to serve — the kernel `ReviewRequest` carries only `id/caller/tool/arg_summary`, so target and staged change are always absent and the only injection-resistant facts (tool, args, caller) moved from default visibility into a collapsed `View details` disclosure, leaving a frontend-authored constant as the headline (confirmed). Two module headers claim more than the code delivers: "every decision point in the shell routes through here" while live `ConfirmDialog` approvals remain in `ProviderHub` and `SmartTableViewer`, and "the user sees the subject, target, and staged change" for a fact that never carries them (confirmed). Approve also lost its danger affordance (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The registry itself is a genuine single authority for the kinds it owns: `DECISION_KINDS` is a frozen tuple, `decisionPresentation` throws on an unregistered kind instead of degrading, and the kind→presentation table is the only place placement/tone live. Adapters are the only fact constructors, and none of them invents a target, diff, or outcome — `approvalFact` leaves `staged` undefined when the kernel omits before/after, and that behaviour is pinned by a test. The three unused kinds (progress, choice, capture) have presentations but no adapters and no consumers, and nothing in the scoped files presents them as wired.

The authority claim is nevertheless not yet true shell-wide. `ProviderHub`'s "Remove provider?" and `SmartTableViewer`'s AI-column cost gate are approval-kind decision points still rendered by hand-built `ConfirmDialog` bodies, one of them pasting a raw kernel error string as prose. That is a live bypass path relative to the v43 rule, and it directly contradicts the "every decision point" line in `DecisionSurface.tsx`.

The ReviewGate security properties survive the swap. The fact is built only from gate-derived fields, approval still travels `review_resolve` over the Tauri command surface an external MCP caller cannot reach, and the fail-closed edges are intact: Esc, backdrop, and any unknown option id all resolve to deny, and initial focus parks on Deny through `initialFocusRef`. What regressed is legibility and risk signalling: with the kernel supplying no subject/target/staged change, the modal reads "Review change / A consequential action needs approval / View details", and Approve renders as an ordinary primary button because `approvalFact` never sets `destructive`.

The AmbientHome stale-selection path matches the accepted behaviour: on a failed `resolveFctSelection` inside `send`, it raises one `unavailable` fact, returns the session to Auto, queues a runtime reset, and returns without dispatching the turn. Two Playwright tests drive the real composer and pass. Fabricated assistant prose is gone from the FCT paths but still present for runtime-reset and resource-switch failures in the same file, two of which are newly added lines, so the shell reports the same class of failure two different ways.

ADR-003 v43 follows PROCESS: version bumped, `last_updated` set, section entry and changelog appended, body section added, INDEX row updated with the v43 summary. The repo-wide governance gate currently blocks on three files outside this scope.

### One authority, closed kind set, and where the bypass still is

The kind set closes at the type level: `DecisionKind` derives from the `DECISION_KINDS` tuple and `REGISTRY` is keyed `Record<DecisionKind, DecisionPresentation>`, so a seventh kind cannot be typed or rendered without editing both. Unregistered kinds throw instead of degrading, and tests pin the six-element order.

The bypass is outside the registry, in surfaces that were not migrated:

```
DecisionSurface (registry)          ConfirmDialog (hand-built)
  ├── ReviewGateHost   approval       ├── ProviderHub      "Remove provider?"
  └── AmbientHome      unavailable    └── SmartTableViewer "Run AI column?"
```

`SmartTableViewer` is the sharper case: the kernel `needs_confirmation` cost gate is an approval decision, and its body is the raw error message interpolated into prose (`${msg}\n\nRun it anyway?`) — the shape v43 forbids. `DiscardConfirm` is now referenced only from a comment in `Modal.tsx`, so it is dead rather than a live bypass.

### Approval: security preserved, legibility regressed

Approval still resolves through `review_resolve` on the intra-process Tauri surface (`commands/review.rs`), which the external brain cannot reach. Fail-closed edges hold in every direction: `onResolve(optionId === 'approve')` denies on any other id, Esc and backdrop route through `safeDefaultOption` to the `discards` option, and initial focus lands on Deny via `initialFocusRef`.

What the human actually sees is the problem. Production requests carry no `subject`, so the headline is the adapter's constant:

```
Review change
A consequential action needs approval
▸ View details            ← caller, tool, arg_summary live here
[ Deny ]  [ Approve ]
```

Before this change the caller, tool, and argument summary were on screen by default in a monospace block. The v43 changelog frames the old dialog's tool + arg summary as the defect, but the fix it describes — target and staged change — requires facts the kernel does not produce, and option B explicitly declines to add cross-boundary schema. The result is strictly less information at the moment of decision, on the one surface where an injected call has to be caught. `preconditions` is also always `[]` here, and the modal branch ignores `presentation.tone` (only the inline card applies a tone class), so approval's `caution` tone is inert.

### Stale FCT selection

Both failing paths behave as accepted. `selectFct` raises the fact and returns `false` without committing the selection; the `send` path raises it, calls `setSelectedFct(sessionId, null)`, queues an engine reset, releases turn ownership, and returns before any dispatch, so no turn is sent under stale context. The `ownsTurn()` guard wraps both so a stale closure cannot raise a decision for a session the user has left. `unavailableFact` keeps the kernel reason in provenance and turns recovery into a `navigates` option that `AmbientHome` wires to `onSidebarSelect('library')`.

Two Playwright specs drive the shipped composer against a mocked `gate_invoke` and assert the rendered kind, intent attribute, recovery button, the reason living behind the disclosure, the selector reverting to Auto, and the absence of an injected assistant reply. Both pass locally.

Not tested: the approval kind has no component or e2e coverage at all — no test asserts Deny-by-default focus in the rendered modal, Esc/backdrop denying, or the provenance disclosure. The `progress`, `choice`, and `capture` presentations have no test beyond the registry-completeness loop. Conflict is covered only at the adapter level, not rendered.

### Conformance attributes are inline-only

`data-decision-kind` and `data-decision-intent` are set on the inline `<section>` but not on the modal, so approval — the kind v43 cares most about — cannot be traced by the same selector the e2e suite uses for inline decisions.
