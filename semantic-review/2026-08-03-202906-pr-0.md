# Companion bootstrap and session isolation fixes leave ownership and handoff gaps

The rework removes the clean-install LibreOffice bootstrap deadlock, serializes Irisy transcript-owner resets ahead of sends, makes the confirmed Coding workspace switch fail closed, and makes AGENTS projection rewrites atomic. Three behavioral gaps remain in projection retirement and Coding workspace handoff. **Watch for:** **confirmed** projection ownership can still be inferred from a user-authored near-match; **confirmed** an empty-transcript workspace switch bypasses engine reset; **confirmed** several composer and workspace actions remain enabled during a handoff.

**Verdict**: NEEDS_CHANGES

## High-level view

LibreOffice Companion now creates its dedicated credential before publishing a rendezvous containing only schema, protocol, PID, and port. Rust validates the rendezvous process identity before retrieving the credential and rechecks identity afterward, removing the circular startup dependency without placing the bearer secret in the rendezvous.

AGENTS updates now use synchronized sibling temporary files plus rename. **Confirmed:** projection retirement still recognizes a broad family of objects rather than proving the exact generated gate shape, leaving a user-authored near-match under `ctrl-kernel` at risk of deletion.

Irisy queues engine reset whenever transcript ownership changes and sends await that queue. Coding’s confirmed switch also awaits reset and retains the old workspace on failure, but **confirmed:** the no-session path changes workspace identity without resetting the singleton backend process.

**Confirmed:** the main Coding input and workspace tabs are disabled during confirmed handoff, while attachment, refresh, target selection, and launch actions remain interactive. The handoff is therefore only partially exclusive.

1. **Incomplete projection ownership proof — confirmed** — `managed_kernel_entry()` accepts user-authored near-matches as managed. Require the exact generated shape or a durable ownership fingerprint before deletion and add near-shape preservation tests.
2. **Empty-transcript workspace reset bypass — confirmed** — `requestWorkspaceChange()` directly commits a new workspace when `hasSession` is false although an old-cwd ACP process may still exist. Await reset for every non-initial identity change or enforce cwd in the backend.
3. **Partial handoff control gate — confirmed** — attachment, refresh, target selection, and launch actions remain enabled while workspace reset is pending. Gate all composer and workspace-affecting controls on `switchingWorkspace` and test the complete disabled surface.

<details><summary>Details</summary>

## Secret-free LibreOffice bootstrap is no longer circular

The extension creates or reads `app.ctrl` / `libreoffice-bridge` before binding and publishing its random loopback endpoint. `resolve_macos_spawn_environment()` validates the signed process before `ensure_bridge_credential()` reads the secret, then rechecks process identity. This resolves the prior deadlock while preserving ADR-010’s trust-boundary ordering.

## Projection retirement does not prove exact CTRL ownership

**Confirmed:** `managed_kernel_entry()` in `src-tauri/src/kernel/projector.rs` checks selected remote-gate fields: a numeric loopback URL ending in `/mcp`, a non-empty bearer value, expected caller and intent headers, expected type, and enabled state. It does not require exact object and header key sets, reject added custom fields, validate a nonzero `u16` port, or compare a durable ownership signature. A user replacement retaining those recognizable fields can therefore be classified as managed and deleted during retirement.

The preservation test covers a clearly different local-command replacement, not near-managed forms accepted by this predicate. Retirement should compare the complete generated representation or a durable ownership fingerprint, with tests for extra object keys, extra headers, malformed or out-of-range ports, and modified values under the managed key.

## Empty-transcript Coding workspace changes can retain the old process

**Confirmed:** `requestWorkspaceChange()` in `CodingAgentPanel.tsx` stages and resets only when `hasSession` is true; otherwise it directly invokes `setWorkspaceId(nextId)`. The backend cannot validate the transition because `coding_chat.rs` fixes `stale_cwd` to false and treats the PWA reset as authoritative. Messages can be empty while an ACP process still exists, allowing the next send to reuse a process launched in the previous workspace.

Every non-initial workspace transition should pass through the staged, awaited reset before committing identity, or the backend must track and enforce process cwd. Coverage needs the empty-transcript/live-process case.

## Coding handoff leaves concurrent controls active

**Confirmed:** `switchingWorkspace` gates the textarea, send action, workspace tabs, and confirmation controls, but not the attachment button, refresh action, external target selector, or editor/shell launch controls in `CodingAgentPanel.tsx`. Those actions can run while reset is in flight against an identity that is still changing.

The handoff state should gate every composer and workspace-affecting action. A component-level test should assert that all such controls remain disabled until reset succeeds or fails.

## Missing regression coverage follows the remaining gaps

**Confirmed:** targeted tests do not cover a near-managed projection replacement, an empty-transcript Coding switch with a live backend process, or the complete handoff disabled-state surface. These cases should be added with the corresponding fixes.
