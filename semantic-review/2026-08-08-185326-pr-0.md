# Decision surface registry — fix pass over the seven prior findings

Third pass over the uncommitted decision-surface slice. All seven findings from the previous review are closed in code, tests, and ADR text: `approvalFact` now carries an always-visible `facts` array holding the gate-derived caller/operation/arguments and marks Approve `destructive`; the `DecisionSurface` and `ReviewGateHost` headers state the honest migration state instead of claiming shell-wide authority or a target/staged change the kernel never sends; ADR-003 v43 records U10 as only partially served and lists ProviderHub/SmartTableViewer, kernel-side target facts, approval rendered coverage, and the three unused kinds as open Design Acceptance; the three remaining fabricated assistant failure messages in `AmbientHome` (session switch, turn stop, resource switch) now raise `unavailable` facts; and pending decisions queue with id dedupe in both `AmbientHome` and `ReviewGateHost`. Each drift guard also holds: default focus still parks on the non-committing option, approval still resolves over the `review_resolve` Tauri command an external caller cannot reach, tone and `data-decision-*` now apply to the modal body as well as the inline card without being emitted twice, and every decision-critical fact is stated in `subject` or `facts` rather than only in provenance.

Watch for: one same-class residual outside the seven — the provider-readiness path still injects an assistant message ("I don't have a model yet…", reworded in this diff) for what is an `unavailable` condition with a navigation recovery (confirmed). Decision ids are `${prefix}-${Date.now()}`, so two failures of the same kind inside one millisecond would dedupe to one (confirmed as a code property, unlikely to trigger since each path sits behind an await). Neither blocks.

**Verdict**: APPROVED

## High-level view

The approval surface is now the most informative version of itself. `approvalFact` builds `facts` from `caller`/`tool`/`arg_summary` and leaves `provenance` empty, so the injection-resistant fields are on screen at decision time; the optional richer fields still populate `target`/`staged`/`preconditions` only when an owner supplies them, and the "never fabricates a staged change" test still pins that. Approve carries `destructive: true`, which `Actions` maps to the `danger` button variant, and `safeDefaultOption` plus `initialFocusRef` keep first focus on Deny.

Comment truth matches code. `DecisionSurface`'s header names the two migrated consumers and states that `ProviderHub` and `SmartTableViewer` still hand-build approval dialogs as tracked open Design Acceptance; both are in fact still on `ConfirmDialog`, so the claim is accurate rather than aspirational. `ReviewGateHost` no longer says the user sees target and staged change; it says the gate-derived facts stay visible and that U10 needs a fact-owner amendment.

ADR-003 v43 carries the same honesty into authority: the changelog and the § decision-registry body state that U10 remains partially served, that a replacement surface may not be less informative than what it replaced, and that queued decisions are never silently dropped. The Design Acceptance block lists four unchecked migration items covering the hand-built dialogs, the kernel-side target/staged facts, rendered approval coverage, and the unwired `progress`/`choice`/`capture` kinds. INDEX is in sync.

`AmbientHome` routes all five failure paths through `unavailableFact` — FCT select, stale FCT at send, session switch, turn stop, resource switch — each guarded by `ownsTurn()` where a stale closure could otherwise speak for a session the user left. `raiseDecision` appends to a `DecisionFact[]` and skips duplicates by id, `decisions[0]` renders, and the surface shows `+N more waiting`, so a second failure no longer erases an unseen first. The prose that remains in the file is either the turn's own streamed result or the provider-readiness guidance, not a fabricated failure report.

The registry suite now asserts visible gate-derived facts with empty provenance, the destructive committing option, non-committing default focus, and that no decision-critical fact lives only in provenance. Not tested: the approval kind still has no rendered coverage — no test drives Deny-by-default focus, Esc/backdrop denying, or the visible fact rows in the mounted modal. That gap is now a tracked acceptance item rather than undisclosed.
